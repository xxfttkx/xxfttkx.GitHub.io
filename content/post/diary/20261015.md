看[frida文档](https://frida.re/docs/javascript-api/#interceptor)才知道

```
The callbacks provided have a significant impact on performance. If you only need to inspect arguments but do not care about the return value, or the other way around, make sure you omit the callback that you don't need; i.e. avoid putting your logic in onEnter and leaving onLeave in there as an empty callback.
```

所以之前写的这种抽象算是浪费了很多性能：

```
  return Interceptor.attach(method.virtualAddress, {
    onEnter(args) {
      if (!quiet && (mod === undefined || mod.enabled)) {
        log(logEnter);
      }
      if (onEnter) {
        // InvocationContext 可能直接是 CpuContext 或持有 .context 字段，两者兜底
        const self = this as any;
        const ctx: CpuContext = self.context ?? self;
        const guardedEnter = mod ? guarded(mod, onEnter) : onEnter;
        guardedEnter(cls, method, args, ctx, self as InvocationContext);
      }
    },
    onLeave(retval) {
      if (onLeave) {
        const self = this as any;
        const ctx: CpuContext = self.context ?? self;
        const guardedLeave = mod ? guarded(mod, onLeave) : onLeave;
        guardedLeave(cls, method, retval, self as InvocationContext, ctx);
      }
      if (!quiet && (mod === undefined || mod.enabled)) {
        log(logReturn(retval));
      }
    },
  });
```

rdr2的赌徒挑战做的很烂，例如我现在在赌徒挑战8，它要求我在要牌3次以以上时获胜，但它又不考虑我过去的所有对局，这就会导致让我很容易想到特意来刷这种条件的胜场，即每局无脑要牌，20点了也继续要牌，只因为没达到要求；因为正常玩很难达成，我也不会特意在这个时间点因为瘾大来大力出奇迹。
